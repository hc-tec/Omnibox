# 工作台核心概念与架构规范

> 本文档记录工作台（Workspace）的核心概念区分和架构设计原则，是开发工作台相关功能时的必读文档。

## 核心概念区分

### 1. 数据产物 (Data Artifacts / data_stash)

**本质**：原始数据或经过中间加工的数据

**来源**：
- `fetch_public_data` - 从 RSSHub 等公开数据源获取的原始数据
- `data_operator` - 经过 Python 代码处理（过滤/聚合/转换）后的中间数据
- 其他数据处理工具

**用途**：
- ✅ 后端上下文引用：作为后续工具的输入
- ✅ 供其他工具进一步加工
- ✅ 调试/审查：让用户查看原始数据长什么样
- ❌ **不是**用户最终看到的可视化内容

**前端展示**：
- **不需要 Pin 功能**：因为前端不知道如何渲染它们
- 仅作为参考/调试面板显示
- 可以查看原始数据结构

**定位**：幕后角色，不是主角

---

### 2. 面板 (Panels)

**本质**：经过 `emit_panel_preview` 工具处理后，明确告诉前端"这个数据应该以什么形式展示"的结构化输出

**来源**：
- `emit_panel_preview` 工具
- 该工具由 Agent（如 ResearchAgent）决定何时调用

**用途**：
- ✅ 用户真正看到的可视化内容
- ✅ 列表卡片、图表、表格等组件渲染
- ✅ 符合前端组件契约（ListPanel-contract-v3 等）

**前端展示**：
- **需要 Pin 功能**：可固定到仪表盘长期监控
- **应该展示在画布中央**：这是主角
- 支持多种视图切换（图表/表格/文本/原始）

**定位**：前台主角，用户交互的核心

---

### 3. 步骤信息 (Steps)

**本质**：工作流执行的各个阶段

**内容示例**：
1. 规划（Router/Planner 决策）
2. 数据获取（fetch_public_data）
3. 数据处理（data_operator）
4. 分析（extract_insights）
5. 面板生成（emit_panel_preview）

**前端展示**：
- 应该集中展示在一个地方（如侧边栏）
- 让用户知道执行进度
- 每个步骤可展开查看详情

---

### 4. 思考信息 (Thinking/Reasoning)

**本质**：Agent 的推理过程和决策逻辑

**内容示例**：
- 为什么选择这个工具
- 如何分析当前数据
- 下一步计划是什么
- 决策依据和推理链条

**参考**：Manus 的做法——透明展示思考链条

**前端展示**：
- 应该可见，让用户理解 Agent 的决策逻辑
- 可以折叠/展开，不占用主要空间
- 提升用户对系统的信任度

---

## 架构流程图

```
用户查询
    ↓
Router → ResearchAgent（产生思考信息）
    ↓
工具调用
    ├── fetch_public_data → 数据产物（中间数据，幕后）
    ├── data_operator     → 数据产物（加工数据，幕后）
    └── emit_panel_preview → 面板（可视化，前台主角）
    ↓
用户看到：
    ┌─────────────────────────────────────────────┐
    │  步骤面板        │       面板（可 Pin）       │
    │  （可展开）      │       （画布中央）         │
    │                  │                           │
    │  思考信息        │                           │
    │  （透明可见）    │                           │
    │                  ├───────────────────────────│
    │                  │   数据产物（参考/调试）    │
    │                  │   （不需要 Pin）           │
    └─────────────────────────────────────────────┘
```

## 当前工作台问题清单

1. **画布中央空空如也**
   - 问题：没有展示面板
   - 应该：展示 `emit_panel_preview` 产出的可视化内容

2. **数据产物被当成主角**
   - 问题：数据产物占据了右侧主要面板
   - 应该：数据产物只是参考/调试用途，不是主要内容

3. **步骤信息没有展示**
   - 问题：用户不知道执行了什么步骤
   - 应该：有专门的步骤面板，类似研究视图的左侧

4. **思考信息没有展示**
   - 问题：用户不知道 Agent 在想什么
   - 应该：展示 Agent 的推理过程，提升透明度

5. **Pin 功能放错对象**
   - 问题：数据产物有 Pin 按钮
   - 应该：面板（Panels）需要 Pin，数据产物不需要

## 设计原则

### 1. 面板是第一公民
- 面板是用户最终看到的内容
- 面板决定了数据如何可视化
- 面板可以被 Pin 到仪表盘

### 2. 数据产物是幕后英雄
- 数据产物支撑面板的生成
- 数据产物可以被引用和加工
- 数据产物不直接展示给用户（除了调试场景）

### 3. 透明度是信任的基础
- 步骤信息让用户知道进度
- 思考信息让用户理解决策
- 错误信息让用户知道哪里出问题

### 4. 职责分离
- `fetch_public_data`：只负责获取数据
- `data_operator`：只负责处理数据
- `emit_panel_preview`：只负责定义展示方式
- Agent：负责决策和编排

---

## 与研究视图的关系

研究视图（ResearchView）已经正确实现了步骤展示和面板渲染：
- 左侧：执行步骤、研究计划
- 右侧：数据面板、分析结果

工作台（Workspace）应该复用这些设计模式，但增加：
- Session 持续性（多轮对话）
- 保存为模板功能
- 更灵活的数据引用机制
